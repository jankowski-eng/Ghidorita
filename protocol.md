# Protocol (spike)

JSON-RPC 2.0 over WebSocket, text frames, one JSON object per frame. Types: `protocol.ts` (authoritative for shapes).

## Process contract
- Electron spawns `python sidecar/main.py`; the sidecar binds `127.0.0.1` on an ephemeral port and prints the port as the **first stdout line** (just the integer). Everything else goes to stderr.
- The sidecar exits when stdin closes (Electron died) or on SIGTERM. **Before exiting it saves unsaved edits** and closes the program and project. Exit 0 means the close completed; a save failure exits 1 and a queued close that has not started within 45 seconds exits 2. One client at a time. One sidecar per projects dir: a second one answers project-touching requests with `ProjectLocked` (see Errors).
- Shutdown contract for clients: call `save` first (to show progress), then close stdin (or SIGTERM), and give the process a long grace (tens of seconds) before SIGKILL: a SIGKILL loses everything not yet saved (see Persistence and crash safety).
- Addresses are **unsigned** hex strings (up to 64 bit; the sidecar never sends a negative offset). Default space: `"0x401000"` (lowercase, no padding). Other spaces are space-qualified: `"<space>:<hex>"`, overlay spaces `"<space>::<hex>"` (Ghidra's spelling): `"code:1000"`, `"OVL1::1000"`. Split at the last `:`, a trailing `:` belongs to the space name. Input also takes `"ram:401000"` (qualified default space) and, when the default space is segmented (x86 real mode), Ghidra's `"1000:0042"`; such addresses are sent back as the linear `"0x10042"`; an unknown space or an offset beyond 2^64-1 is `InvalidArgument`. There are no row indexes: the listing is addressed by address only. Every method that takes or returns an address uses this form, including `list_functions` entries and function-based panels (functions inside overlay or other spaces have qualified `entry` values).

## Requests (client → server; replies are standard JSON-RPC results)
Params/results are in `protocol.ts`; all addresses are lowercase hex strings. Missing or malformed params fail with `InvalidArgument` (-32602). Every method except `open_binary`, `cancel_open`, `cancel_decompile`, `import_candidates`, `list_languages`, `list_programs`, `delete_program` and `close_program` fails with `NoProgram` until a program is open (and while an open is in progress).

### Open / decompile / listing
| method | params | result | semantics / errors |
|---|---|---|---|
| `open_binary` | `{path, loader?, language?, compilerSpec?, baseAddress?, profile?}` | `{programId, name, persisted}` | Options: see *Import options* below; all omitted = default import (full analysis). `programId` is the file's sha256 (default import) or `sha256-<12 hex>` (explicit options); the analyzed program is stored in a Ghidra project (`$SIDECAR_PROJECTS_DIR`, default `~/Library/Application Support/ghidra-desktop-spike/projects`); `persisted` is true when loaded from there without re-analysis. Otherwise imports, analyzes, saves; emits `progress`; replies when done. `Busy` if another open is running (nothing else changes); `Cancelled` after `cancel_open`. **End state:** the current program is saved and closed first; after any failure (`NotFound`, `InvalidArgument`, `Cancelled`, `Internal`, ...) **no program is open** and nothing of the failed open is stored. The one exception: if saving the old program fails (`Internal`, "save failed before closing"), the old program stays open. |
| `cancel_open` | `{}` | `{cancelled}` | Cancels the running `open_binary` (it fails with `Cancelled`, nothing is saved). `false` if no open is running. |
| `list_functions` | `{}` | `[{name, entry, size, source}]` | Every non-external function of every space, in Ghidra's address order (spaces in space order, ascending inside a space). `entry` is a protocol address. `source` = where the name came from: `user`, `analysis`, `imported`, `default`. |
| `decompile` | `{entry, timeoutSecs?=30}` | `{text, tokens[], cached}` | `NotFound` if no function at `entry`; `Timeout` after `timeoutSecs` (the client may retry with a long one, "decompile anyway"); `Cancelled`. A function body over ~30 KB (`size` from `list_functions`) can take a minute or more: clients warn first. |
| `cancel_decompile` | `{id}` | `{cancelled}` | Cancels the `decompile`, `variable_uses`, `rename_variable` or `retype_variable` request with that JSON-RPC id, queued or running; that request fails with `Cancelled` (a cancelled variable edit writes nothing). `false` if unknown or finished. |
| `listing_info` | `{}` | `{ranges:[{start,size}], totalBytes}` | The loaded+initialized address set of **all** address spaces (overlay blocks included), in traversal order: Ghidra's address order, spaces in space order, ascending inside a space. `start` is space-qualified. The client maps scroll position ↔ address by cumulative range size in that order (see `app/src/renderer/addrmap.ts`) and does not re-sort. |
| `listing_rows` | `{address, count, direction?="forward"}` | `ListingRow[]` | See below. |

### Data types
The data type manager works on the open program's own `DataTypeManager` ("program", writable) and Ghidra's built-ins ("builtin", read-only). Types are addressed by Ghidra path name (`"/Mine/Point"`, `"/char *"`, `"/int[4]"`); `kind` ∈ struct\|union\|enum\|typedef\|pointer\|function\|array\|builtin. Not offered: opening `.gdt` archives, moving types between categories, editing typedef targets or function definitions (they are shown read-only).
| method | params | result | semantics / errors |
|---|---|---|---|
| `dt_sources` | `{}` | `[{id, name, writable}]` | `program` (named like the program) and `builtin`. |

| `get_data_type` | `{path, source?}` | `DataTypeDetail` | Node fields plus `source`, `writable`, `description`, `archive` (non-local source archive or null). struct/union: `packed`, `packingValue`, `minAlign`, `alignment`, `components[{ordinal, offset, length, type, typePath, name, defaultName, comment, undefined, bitfield}]`. **All** components are listed: an unpacked struct has one `undefined` 1-byte filler component per free byte (`type` `"undefined"`, `name` null). enum: `values[{name, value}]` (value = decimal string, sorted by value). typedef/pointer/array: `base`, `basePath` (`elements` for arrays). function definition: `signature`. `NotFound`. |
| `create_data_type` | `{kind, name?, category?="/", size?, base?}` | `{path}` | `kind` struct (`size` bytes of undefined filler, default 0) \| union \| enum (`size` 1/2/4/8, default 4) \| typedef (`base` = type text) \| pointer (to `base`; no name, result is the pointer type's path, e.g. `/S *`; idempotent) \| category. | `delete_data_type` | `{path, category?=false}` | `{}` | Deletes a type (data using it is cleared by Ghidra) or, with `category`, an **empty** category. Undo label "Delete <path>". `NotFound`; `InvalidArgument` for a non-empty category or the root. |
| `rename_data_type` | `{path, newName}` | `{path}` | Undo label "Rename data type <old> to <new>". `InvalidArgument` for a duplicate or invalid name. |
| `edit_struct` | `{path, op}` | `{}` | struct or union; `op` as in `protocol.ts` `StructOp`. One transaction, undo label `Edit <name>: <op>` (e.g. `Edit S1: add`); a failure rolls back. Semantics measured on Ghidra 12.3 (see SPIKE_REPORT, Round 5): **unpacked** structs keep offsets: `set` on a filler byte consumes following filler (error if not enough), `set` to a smaller type leaves filler behind, `clear` turns a field into filler, `delete` removes it and shifts later fields up (struct shrinks), `insert`/`add` grow it, `resize` pads with filler or cuts. **Packed** structs have computed offsets; `move` (reorder) works only there and on unions; `resize` only on unpacked structs. `pack {packed:true}` uses default packing unless `packingValue` is given; `packed:false` keeps the current offsets. Bit-field components cannot be edited/moved. `InvalidArgument`: bad/missing ordinal, unknown or dynamic type, a struct containing itself by value, no room, wrong kind; `NotFound`. |
| `edit_enum` | `{path, op}` | `{}` | `op` as `EnumOp`: `set` adds or updates (values accept decimal, `0x…`, negative and up to 2^64-1, as strings), `oldName` renames, `remove`, `resize` (size 1/2/4/8: Ghidra's `EnumDB` has no setLength, so the type is replaced by a copy and instances follow). Undo label `Edit <name>: <op>`. |
| `create_struct_from_data` | `{address, length, name, category?, apply?=true}` | `{path}` | Builds a struct of `length` bytes from the code units at `address`: each defined data item becomes a component of its type, undefined bytes stay filler. The range must start and end on item boundaries and contain no instruction. With `apply` (default) the struct is also defined at `address` (`CreateDataCmd`, clears conflicting data) in the same transaction "Create structure <name>". `InvalidArgument` otherwise (also for an existing name). Fires `program_changed` kinds `type` and, when applied, `data` with the range. |
| `auto_create_structure` | `{entry, name, structName?}` | `{path}` | Ghidra's "Auto Create Structure" (`FillOutStructureHelper`, the helper behind `FillOutStructureCmd`) on the decompiler local/param `name` of the function at `entry`: fields are inferred from the loads/stores at offsets from that variable (also followed into callees), a new struct is added (default name `auto_struct…` in `/auto_structs`, or `structName`; **without** `structName`, a variable that already points to a struct extends that struct, as Ghidra's action does, and `path` is that struct), and the variable is retyped to a pointer to it, all in one transaction "Auto create structure in <function>". Runs on thread R with a short-lived decompiler like `retype_variable` (callee decompiles included, so it can take seconds). `NotFound` function/variable; `InvalidArgument` when nothing is accessed through the variable (no struct can be inferred), bad or existing `structName`. |

All data type edits fire `program_changed` with `kinds` containing `type` and `ranges: null` (Ghidra's type events carry no address), so the client refetches listing and decompiler tabs, and the sidecar clears the **whole** decompile cache (`type` is not a range-only kind). Applied data follows a changed struct (Ghidra resizes/clears instances); editing a struct is therefore also a listing edit.

### Import options
- `open_binary` options are all optional: `loader` (a candidate's loader name), `language` (LanguageID), `compilerSpec` (default: language's default), `baseAddress` (hex string, `0x…`, must fit the address space; only valid if the chosen candidate has `acceptsBaseAddress`). Unknown loader/language/compilerSpec or a malformed/out-of-range base address → `InvalidArgument`.
- **Persistence key.** No options → `programId = sha256(file)`, the project file is named by it: unchanged, so existing projects still load. Any option present → `programId = sha256(file) + "-" + hex(sha256(canonical)[:6])`, where `canonical` = JSON of `{"loader","language","compilerSpec","baseAddress"}` (compact separators `,` `:`, keys in that order, absent = `null`, `baseAddress` normalised to lowercase `0x…` without leading zeros). The same file with different options never collides with the default import or with each other. When the sidecar runs with `SIDECAR_ANALYSIS_DISABLE` (analyzers switched off for first-open analysis), `canonical` gets a fifth key `"analysisDisable"` (the sorted analyzer names) and counts as an option, so a reduced analysis never shares a key with a full one. **Analysis profile.** `profile` is not an import option and not part of `canonical` by itself: `"full"` (all analyzers) leaves the key as above; `"fast"` switches off `Call Convention ID`, `Decompiler Switch Analysis` and `Stack` (Round 5 `FAST_PROFILE`; measured in SPIKE_REPORT round 4: about 2.4x faster first open on a 66 MB binary, fewer recovered switch tables and about 3-5% fewer call references) and so adds `analysisDisable` as above; this is the same key the env var produced in round 4. Omitted `profile` = the process-wide `SIDECAR_ANALYSIS_DISABLE` if set, else `"full"`; an explicit `"full"` beats the env var. Anything else is `InvalidArgument`. A fast program records `profile: "fast"` in its `list_programs` `options` (and `open_binary` with those options reopens it); a full one records nothing. Passing the preferred spec explicitly is a different key from the default (the UI omits options for the default path). Opening with options whose key is already persisted loads it without re-analysis.

Each edit is one Ghidra transaction, named as the undo label (e.g. "Rename symbol"), runs on thread R, and fires `program_changed`. Result `{}` unless noted.

|---|---|---|---|

`listing_rows` walks code units from an anchor, no index. `forward`: starts at the code unit containing `address` (or the next one if `address` is in a gap) and goes up. `backward`: the `count` code units strictly before the one containing `address`, returned in ascending order. Both are restricted to the loaded+initialized set; fewer than `count` rows means the end (or start) was reached. `count` is capped at 1000. The walk continues across address spaces in the order of `listing_info`. A row is one code unit (instruction, defined data, or one undefined byte); `bytes` shows at most 16 bytes and `bytesMore` says how many more the unit has (shortcut: no way to fetch them, upgrade with a `get_bytes` RPC). Row fields (`ListingRow` in `protocol.ts`):
- `label` the primary symbol; `labels` all symbols at the address, primary first, only when there is more than one.
- `comment` is the EOL comment; `pre`, `post`, `plate`, `repeatable` the other kinds (multi-line text), each only when set. The client renders plate and pre above the row, post below it, EOL and repeatable at the end of the line.
- `header` on a function's entry row: `signature`, `convention`, `params` (count), `paramBytes` / `localBytes` (stack frame sizes), `noReturn`, `thunk`.
- `xrefs` `{count, items}` when memory references point at the address: `count` is the full number, `items` at most 5 (shortcut: the first 5 Ghidra returns, shown ascending by from; the full list is `xrefs_to`), each `{from, kind}`.
- `parts` for defined structure/union/array data: components `{offset, length, type, name, value}` (arrays name elements `[i]`), at most 64 (`partsTotal` is the real count when cut; shortcut: one level, nested composites show as one component with their display value). The client folds them by default.
Row building stays on thread R and costs a few Ghidra calls per row; bench numbers are in SPIKE_REPORT.

## Tokens
`line` is 0-based into `text.split("\n")`. `colStart/colEnd` index into that line (indent included). `kind` follows Clang syntax types. `targetFunction` is set on call-target name tokens when the callee entry is known (thunks are followed to the entry of the called function symbol itself, not resolved).

## Notifications (server → client, no id)
- `progress {phase, pct, message, analyzer?, done?, total?}` — phase order: `import` → `analysis` → `saving` → `ready` (only while `open_binary` runs; a persisted program goes straight to `ready`). `pct` is 0–100 or -1 (indeterminate). During `analysis` `pct` is -1 because Ghidra's AutoAnalysisManager has no global total; `analyzer` is the current analyzer name; `pct` is the per-analyzer progress/max when that analyzer reports a maximum (else -1); `done` is the number of analyzer runs finished so far; `total` is omitted.
- `program_changed {ranges, kinds, undo}` — the program was modified. `ranges` is `[{start,end}]` (Ghidra address ranges, space-qualified, `end` inclusive, both ends in one space) or `null` = unknown/broad, refetch everything. Type changes (`kinds` has `type`) always carry `null`: Ghidra's type events have no address. A client refetches only the listing rows that intersect `ranges`. `kinds` ⊆ symbol|comment|function|data|code|type|other tells the client what to refetch. `undo` is the new `UndoState` (including `dirty`). Coalesced over ~50 ms (ranges merged, kinds unioned); changes still pending when the program is closed are dropped (no notification after `close_program`). Fired for edits, for `undo`/`redo` (which send `ranges: null`) and for `save` (`ranges: []`, `kinds: []`: only `dirty` changed, nothing to refetch); never during `open_binary`.
- `error {message}` — non-fatal, out-of-band.

## Errors
Standard JSON-RPC error object. Codes in `protocol.ts` `ErrorCode`: NoProgram -32001, Cancelled -32002, Timeout -32003, NotFound -32004, Busy -32005 (open in progress / second `open_binary`), ProjectLocked -32006, InvalidArgument -32602, MethodNotFound -32601, Internal -32603.

`ProjectLocked` (-32006): another sidecar (another Ghidrette) holds the projects dir; message `projects dir in use by another Ghidrette (<dir>)`. Returned by every request that touches the project (`open_binary`, `import_candidates`, `list_programs`, `delete_program`); the sidecar stays up and the next call retries, so it works once the other instance has quit. `list_languages` and the rest are unaffected.

## Concurrency
- **Thread R** (the event loop dispatches to it) handles the cheap program reads (`list_functions`, `listing_*`, xrefs, ...) and ALL writes, `undo` and `redo`, in arrival order.
- `save`, `close_program` run on R like edits (in order); `import_candidates`, `list_languages`, `list_programs`, `delete_program` also run on R (they touch the project or loaders only when no open is running, hence `Busy` during an open; `close_program` waits for running decompiles to be cancelled as in `_close`). `open_binary` saves the current program before replacing it; a save failure keeps it open.
- **Thread O** runs `open_binary` (import + analysis + save). While an open is in progress, R requests and `decompile` fail fast with `NoProgram`, and a second `open_binary` fails with `Busy`.
- `cancel_open` is handled on the event loop (bypasses the queues): it cancels the TaskMonitor, `open_binary` fails with `Cancelled`, nothing is saved to the project, and the sidecar stays usable.
- **Slow reads (scan workers, thread S)**: `search_symbols`, `list_symbols`, `list_strings` and `search_memory` run on M threads (env `SIDECAR_SCAN_WORKERS`, default 2) with their own queue, so a multi-second scan or search never delays `listing_rows` or edits on R. They read the program concurrently with R (Ghidra's database locking), are cancellable by request id (`cancel_search`), and are cancelled when the program is closed or replaced (`close_program` waits for them like for decompiles). Their cached snapshots (symbol table views, string scans) are dropped on every `program_changed`. A page read racing an edit (`list_symbols` meeting a symbol the edit deleted after the snapshot was taken) is retried once on a fresh snapshot; only if a second edit races the retry does it fail with `Cancelled` ("program changed while reading, retry"). The client refetches on `program_changed` anyway.
- **Decompiler pool**: N threads (env `SIDECAR_DECOMP_WORKERS`, default 2), each owning its own `DecompInterface` and all sharing one queue. A slow decompile never delays listing fetches. `cancel_decompile` (event loop, bypasses queues) works by request id for queued and running requests.
- **Decompile cache**: shared and thread-safe, keyed by function entry, invalidated on `program_changed` (functions overlapping the changed ranges; `ranges` null or kind `type` clears everything), so results are never stale (`cached` is false after an invalidating edit).
- `rename_variable` / `retype_variable` / `auto_create_structure` prepare on scan workers with a short-lived `DecompInterface`, then commit on R only if the program generation and write revision still match. An intervening write returns `Cancelled` so the client can retry. `load_coverage` parses in a file thread and checks the program generation before returning. Each connection admits at most 64 outstanding requests; messages are limited to 2 MiB and worker queues to 128 items. Disconnect cancels queued work and active decompile/search monitors.

## Persistence and crash safety
- Edits live only in Ghidra's in-memory buffers until saved. The sidecar saves (1) on explicit `save`, (2) automatically when a program is closed (`close_program`, or `open_binary` replacing it), (3) on shutdown (stdin EOF, SIGTERM). There is no discard prompt: unsaved edits are always written. Shutdown waits for a running save (a save lock) and for the close-save on thread R, then closes the project (lock files removed; measured: before Round 5 `spike.lock` and `spike.lock~` stayed behind after every exit) before `os._exit`; it logs `close save took ...` / `shutdown: close finished in ...` on stderr. Saving needs no open transaction (edits end theirs) and works while a decompile runs.
- Dirty: `UndoState.dirty` is `program.isChanged()`. A freshly imported, analyzed and saved program is clean. Undoing back to the last save point is clean again; redo is dirty. Ghidra clears the undo/redo stacks on save.
- Atomic: saving an already persisted program is crash-safe (BufferMgr writes a copy `tmp*.ps`, fsyncs, then renames it to the next `db.N+1.gbf`); killed before the rename = the old version is intact.
- Lost on SIGKILL / power loss: edits since the last save or completed recovery snapshot. Every `SIDECAR_SNAPSHOT_SECS` (default 120, 0 = off), a dirty program gets a Ghidra recovery snapshot on R without clearing undo history. The sidecar temporarily disables Ghidra's headless flag for this call so the snapshot is actually written; the next `open_binary` loads with `okToRecover` and restores the edits as dirty. A load failure that is a Ghidra version mismatch, access failure, or out-of-memory never deletes the stored program.
- Not atomic: the first save of a newly imported program (`createDatabase`). A kill mid-save can leave a registered project item with a partial `db.1.gbf` that fails to open. `open_binary` handles this: if opening the persisted item fails, the item is deleted and the binary is imported and analyzed again (`persisted: false`) instead of failing forever.
- **Measured** (`test_raw_import_options_save_reopen_dirty_undo`): saving a changed program clears both the undo and the redo stack, so the client treats save as an undo barrier; `save` on a clean program does nothing and keeps the redo stack.

## Auth
`SIDECAR_TOKEN` is mandatory: the sidecar exits with status 2 and a stderr message when it is unset or empty, unless `SIDECAR_ALLOW_NO_AUTH=1` is set (test-only escape hatch). The WebSocket path is `/<token>`; the mock server ignores the token.
