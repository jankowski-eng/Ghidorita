# Provider protocol

JSON-RPC 2.0 over WebSocket, text frames, one JSON object per frame. Types: `protocol.ts` (authoritative for shapes).

## Process contract

Electron launches the selected provider as a child process. Bind only to `127.0.0.1` on an ephemeral port and print that port as the first stdout line. Send diagnostics to stderr. Reject WebSocket upgrades unless the path is exactly `/<SIDECAR_TOKEN>`, and allow one client at a time. Electron keeps stdin open for the life of the process. Exit cleanly on EOF or SIGTERM after releasing resources and finishing any required saves. Use a nonzero exit status if shutdown loses work.

## Discovery and sessions

The client first sends `provider_info {}`. The result is `{version: 1, provider, capabilities, recovery?}`. A client must reject an unsupported major version before opening a file. It can ignore additive fields and capabilities it does not recognize. Provider IDs must be stable for the provider's lifetime and across launches. When available, recovery includes `snapshotIntervalSeconds`.

Version 1 requires these operations:

| Method | Params | Result |
|---|---|---|
| `active_session` | `{}` | `{sessionId, programId, name}` or `null`. Read-only and callable during an open. |
| `open_binary` | `{path}` with optional advertised import options | `{sessionId, programId, name, persisted}`. A successful open publishes a new session. |
| `cancel_open` | `{id}` | `{cancelled}`. The ID is the JSON-RPC ID of the matching open. |
| `close_program` | `{}` | `{}`. On success there is no active session. |
| `list_functions` | `{}` | Function summaries in traversal order. `[]` is valid. |
| `get_function_at` | `{address}` | A function containing the address or `null`. |
| `listing_info` | `{}` | Ordered, non-overlapping ranges and their summed byte length, using safe integers for sizes. An empty listing has no ranges and zero bytes. |
| `listing_rows` | `{address, count, direction?}` | A page in traversal order. See [Listing rows](#listing-pages). |

`programId` is an opaque provider key. Scope stored keys to the provider and give each provider its own storage. `sessionId` identifies one active open, including when the same stored program is reopened. Every program-scoped request, including `close_program`, must put that ID on the JSON-RPC envelope alongside `id` and `method`. Discovery, open, active-session queries, import choices, project catalog requests, and cancellation requests are unscoped. Reject a missing or stale session with `StaleSession` (-32007) and recheck ownership before committing queued or prepared writes. Clients must discard results, notifications, and cached data from obsolete sessions.

Only one open can run at once. When an open reports progress, include its JSON-RPC request ID in `progress.openId`. A successful cancellation makes that open fail with `Cancelled` (-32002). Return `cancelled: false` for an unmatched, finished, or non-cancellable open. On replacement failure, `active_session` tells the client whether the previous session survived. A failed autosave must retain that session and its dirty edits. A successful open remains committed if a subsequent listing read fails, so the client can retry the read on the same session.

Addresses are canonical unsigned hex strings, up to 64 bits. Use lowercase offsets without padding, for example `0x401000` in the default space, `code:1000` in another space, or `OVL1::1000` for an overlay. The last colon separates the offset, and the full prefix identifies the space. Keep spaces grouped in the provider's order and ranges ascending within each space. Pages follow that order in either direction, skip gaps, and return rows in traversal order even for backward reads. For a forward page, include a row containing the anchor, or start at the next row. For a backward page, exclude the anchor row. A short page marks the corresponding end. Providers accept counts through 1000. PyGhidra also accepts Ghidra-specific address aliases.

### PyGhidra compatibility

The existing unversioned PyGhidra client tools continue to work. Sending discovery opts a connection into version 1, including required session IDs and an explicit open ID for cancellation. The desktop app requires version 1 discovery. PyGhidra's project paths, persistence keys, and recovery format remain compatible.

## PyGhidra method reference

### Open / decompile / listing
| method | params | result | semantics / errors |
|---|---|---|---|
| `open_binary` | `{path, loader?, language?, compilerSpec?, baseAddress?, profile?, analysis?}` | `{sessionId, programId, name, persisted, analysis}` | Options: see *Import options* below. `programId` is the file's sha256 (default import) or `sha256-<12 hex>` (explicit options). `persisted` is true when loaded from the project. Otherwise the sidecar imports and saves, publishes the program and (`analysis` default `"background"`) starts the analysis on its own lane, replying after the swap with the `AnalysisState`. `analysis: "blocking"` keeps the old behaviour (analyzes first, emits `progress`, `cancel_open` then discards everything). A stored program whose analysis is `none`/`partial` resumes in background mode. Validation, cancellation, and load or import failures preserve the current session and its undo history. Saving the current program is part of the swap. If that save fails, the current program stays open and the staged replacement may already be stored. An unreadable stored program is preserved and reported as `Internal` with its ID. `Busy` if another open is running. |
| `cancel_open` | `{id}` | `{cancelled}` | Cancels the running `open_binary` (it fails with `Cancelled`, nothing is saved). `false` if no open is running. |
| `analysis_status` | `{}` | `AnalysisState` | The live analysis state of the open program, see *Analysis*. |
| `start_analysis` | `{profile?}` | `AnalysisState` | Starts or resumes the analysis of the open program on its own lane. `profile` omitted = the recorded one. A finished `fast` program with `profile: "full"` runs only the analyzers fast skipped (same `programId`). No-op if already analyzed at that level. `Busy` ("analysis already running") while one runs. |
| `cancel_analysis` | `{}` | `{cancelled}` | Cancels the running analysis; its results so far stay, the recorded state becomes `partial`. `false` if none runs. Answered on the event loop, like `cancel_open`. |
| `list_functions` | `{}` | `[{name, entry, size, source}]` | Every non-external function of every space, in Ghidra's address order (spaces in space order, ascending inside a space). `entry` is a protocol address. `source` = where the name came from: `user`, `analysis`, `imported`, `default`. A demangled name counts as `imported` when the file's mangled symbol is still at the entry (Ghidra's demangler marks its names as analysis). |
| `decompile` | `{entry, timeoutSecs?=30}` | `{text, tokens[], cached}` | `NotFound` if no function at `entry`; `Timeout` after `timeoutSecs` (the client may retry with a long one, "decompile anyway"); `Cancelled`. A function body over ~30 KB (`size` from `list_functions`) can take a minute or more: clients warn first. |
| `function_graph` | `{entry, timeoutSecs?=30}` | `{blocks[], edges[]}` | Basic blocks of the function at `entry` (Ghidra's BasicBlockModel) in address order: `{start, end, kind, lines}`, `kind` `c` when the decompiler maps C lines to the block (each C line belongs to the block of its first addressed token; the declarations before the first addressed line are dropped) else `asm` with `addr  instruction` lines. Edges `{from, to, kind}` between block starts: `true`/`false` after a conditional branch (`false` = fall through), else `uncond`; calls are not edges. At most 2000 blocks and 200 lines per block. Decompiler-lane request: `Timeout`/`Cancelled` as `decompile`, same cache and invalidation. `NotFound` if no function at `entry`. |
| `call_graph` | `{entry, depth?=2, to?, maxDepth?=10}` | `{nodes[], edges[], truncated}` | Thread R. Without `to`: the functions within `depth` (at most 6) calls of `entry`, callers and callees. With `to`: the union of the routes from `entry` to `to` that are at most one call longer than the shortest one (and at most `maxDepth`, at most 30, calls); `to` is a node even when no route reaches it. Nodes `{entry, name, kind}`, `kind` `import` for an external function or a thunk to one (a leaf, never expanded). Edges `{from, to, sites}`, `sites` = call instructions. At most 300 nodes (`truncated`). `NotFound` if no function starts at `entry` or `to`. |
| `cancel_decompile` | `{id}` | `{cancelled}` | Cancels the `decompile`, `variable_uses`, `rename_variable` or `retype_variable` request with that JSON-RPC id, queued or running; that request fails with `Cancelled` (a cancelled variable edit writes nothing). `false` if unknown or finished. |
| `listing_info` | `{}` | `{ranges:[{start,size}], totalBytes}` | The loaded+initialized address set of **all** address spaces (overlay blocks included), in traversal order: Ghidra's address order, spaces in space order, ascending inside a space. `start` is space-qualified. The client maps scroll position ↔ address by cumulative range size in that order (see `app/src/renderer/addrmap.ts`) and does not re-sort. |
| `listing_rows` | `{address, count, direction?="forward"}` | `ListingRow[]` | See below. |

| method | params | result | semantics / errors |
|---|---|---|---|
| `import_candidates` | `{path}` | `{candidates:[{loader, language, compilerSpec, preferred, acceptsBaseAddress}], sizeBytes, entropy, layout?, profiles?, defaultProfile?, note?}` | `layout` = `{entry, sections:[{name,size,entropy}]}` or null: entry point and sections from the ELF/PE/Mach-O headers (a few reads; first slice of a universal Mach-O); optional for other providers. | `list_programs` | `{}` | `[{programId, name, sourcePath?, sizeBytes, analyzed, analysis, analysisProfile, lastOpened?, options}]` | Programs stored in the project, newest `lastOpened` first. `options` is `{}` for default imports. `analysis` is `none`|`partial`|`done` (stored in `programs.json`; a program from before round 7 reads as `done`), `analysisProfile` the profile that ran; `analyzed` = `analysis == "done"`. | `delete_program` | `{programId}` | `{}` | Removes the program from the project. `Busy` if it is the open program (or an open is running), `NotFound` if unknown. |

### Data types
The data type manager works on the open program's own `DataTypeManager` ("program", writable) and Ghidra's built-ins ("builtin", read-only). Types are addressed by Ghidra path name (`"/Mine/Point"`, `"/char *"`, `"/int[4]"`); `kind` ∈ struct\|union\|enum\|typedef\|pointer\|function\|array\|builtin. Not offered: opening `.gdt` archives, moving types between categories, editing typedef targets or function definitions (they are shown read-only).
| method | params | result | semantics / errors |
|---|---|---|---|
| `dt_sources` | `{}` | `[{id, name, writable}]` | `program` (named like the program) and `builtin`. |
| `dt_children` | `{source?="program", path?="/"}` | `{categories:[{name,path}], types:[{name,path,size,kind}]}` | One category level, lazily; both lists sorted by name (case-insensitive). Pointers/arrays live in the category of their element type (usually `/`). `NotFound` unknown category, `InvalidArgument` unknown source. |
| `get_data_type` | `{path, source?}` | `DataTypeDetail` | Node fields plus `source`, `writable`, `description`, `archive` (non-local source archive or null). struct/union: `packed`, `packingValue`, `minAlign`, `alignment`, `components[{ordinal, offset, length, type, typePath, name, defaultName, comment, undefined, bitfield}]`. **All** components are listed: an unpacked struct has one `undefined` 1-byte filler component per free byte (`type` `"undefined"`, `name` null). enum: `values[{name, value}]` (value = decimal string, sorted by value). typedef/pointer/array: `base`, `basePath` (`elements` for arrays). function definition: `signature`. `NotFound`. |
| `create_data_type` | `{kind, name?, category?="/", size?, base?}` | `{path}` | `kind` struct (`size` bytes of undefined filler, default 0) \| union \| enum (`size` 1/2/4/8, default 4) \| typedef (`base` = type text) \| pointer (to `base`; no name, result is the pointer type's path, e.g. `/S *`; idempotent) \| category. Undo label "Create <kind> <name>". `InvalidArgument`: bad kind/name (no whitespace), unknown `base`, name already in the category (never a silent `.conflict` copy). |
| `delete_data_type` | `{path, category?=false}` | `{}` | Deletes a type (data using it is cleared by Ghidra) or, with `category`, an **empty** category. Undo label "Delete <path>". `NotFound`; `InvalidArgument` for a non-empty category or the root. |
| `rename_data_type` | `{path, newName}` | `{path}` | Undo label "Rename data type <old> to <new>". `InvalidArgument` for a duplicate or invalid name. |
| `edit_struct` | `{path, op}` | `{}` | struct or union; `op` as in `protocol.ts` `StructOp`. One transaction, undo label `Edit <name>: <op>` (e.g. `Edit S1: add`); a failure rolls back. Type text is parsed by Ghidra's `DataTypeParser` (names, `char[8]`, `S *`; the same parser as `define_data`/`retype_variable`; fixed-length types only). Semantics measured on Ghidra 12.3 (see SPIKE_REPORT, Round 5): **unpacked** structs keep offsets: `set` on a filler byte consumes following filler (error if not enough), `set` to a smaller type leaves filler behind, `clear` turns a field into filler, `delete` removes it and shifts later fields up (struct shrinks), `insert`/`add` grow it, `resize` pads with filler or cuts. **Packed** structs have computed offsets; `move` (reorder) works only there and on unions; `resize` only on unpacked structs. `pack {packed:true}` uses default packing unless `packingValue` is given; `packed:false` keeps the current offsets. Bit-field components cannot be edited/moved. `InvalidArgument`: bad/missing ordinal, unknown or dynamic type, a struct containing itself by value, no room, wrong kind; `NotFound`. |
| `edit_enum` | `{path, op}` | `{}` | `op` as `EnumOp`: `set` adds or updates (values accept decimal, `0x…`, negative and up to 2^64-1, as strings), `oldName` renames, `remove`, `resize` (size 1/2/4/8: Ghidra's `EnumDB` has no setLength, so the type is replaced by a copy and instances follow). Undo label `Edit <name>: <op>`. |
| `create_struct_from_data` | `{address, length, name, category?, apply?=true}` | `{path}` | Builds a struct of `length` bytes from the code units at `address`: each defined data item becomes a component of its type, undefined bytes stay filler. The range must start and end on item boundaries and contain no instruction. With `apply` (default) the struct is also defined at `address` (`CreateDataCmd`, clears conflicting data) in the same transaction "Create structure <name>". `InvalidArgument` otherwise (also for an existing name). Fires `program_changed` kinds `type` and, when applied, `data` with the range. |
| `auto_create_structure` | `{entry, name, structName?, timeoutSecs?}` | `{path}` | A scan worker infers fields used by the decompiler variable `name` at `entry`, following it into direct callees one level deep. One transaction on R creates a struct in `/auto_structs` (default base name `astruct`) and retypes the variable to a pointer to it. When `structName` is omitted and the variable already points to a struct, the transaction extends that struct. `timeoutSecs` covers decompilation and inference (default 30 seconds, also used for zero). `cancel_decompile` cancels preparation. `NotFound` for a missing function or variable. `InvalidArgument` when no struct can be inferred or the requested name is invalid or already exists. |

All data type edits fire `program_changed` with `kinds` containing `type` and `ranges: null` (Ghidra's type events carry no address), so the client refetches listing and decompiler tabs, and the sidecar clears the **whole** decompile cache (`type` is not a range-only kind). Applied data follows a changed struct (Ghidra resizes/clears instances); editing a struct is therefore also a listing edit.

### Import options
- `open_binary` options are all optional: `loader` (a candidate's loader name), `language` (LanguageID), `compilerSpec` (default: language's default), `baseAddress` (hex string, `0x…`, must fit the address space; only valid if the chosen candidate has `acceptsBaseAddress`). Unknown loader/language/compilerSpec or a malformed/out-of-range base address → `InvalidArgument`.
- **Persistence key.** No options → `programId = sha256(file)`, the project file is named by it: unchanged, so existing projects still load. Any option present → `programId = sha256(file) + "-" + hex(sha256(canonical)[:6])`, where `canonical` = JSON of `{"loader","language","compilerSpec","baseAddress"}` (compact separators `,` `:`, keys in that order, absent = `null`, `baseAddress` normalised to lowercase `0x…` without leading zeros). The same file with different options never collides with the default import or with each other. When the sidecar runs with `SIDECAR_ANALYSIS_DISABLE` (analyzers switched off for first-open analysis), `canonical` gets a fifth key `"analysisDisable"` (the sorted analyzer names) and counts as an option, so a reduced analysis never shares a key with a full one. **Analysis profile.** `profile` is not an import option and not part of `canonical` by itself: `"full"` (all analyzers) leaves the key as above; `"fast"` switches off `Call Convention ID`, `Decompiler Switch Analysis` and `Stack` (Round 5 `FAST_PROFILE`; measured in SPIKE_REPORT round 4: about 2.4x faster first open on a 66 MB binary, fewer recovered switch tables and about 3-5% fewer call references) and so adds `analysisDisable` as above; this is the same key the env var produced in round 4. Omitted `profile` = the process-wide `SIDECAR_ANALYSIS_DISABLE` if set, else `"full"`; an explicit `"full"` beats the env var. Anything else is `InvalidArgument`. A fast program records `profile: "fast"` in its `list_programs` `options` (and `open_binary` with those options reopens it); a full one records nothing. Passing the preferred spec explicitly is a different key from the default (the UI omits options for the default path). Opening with options whose key is already persisted loads it without re-analysis.

| `export_gzf` | `{path}` | `{path, bytes}` | Writes the open program as a Ghidra archive (`.gzf`, Ghidra's `GzfExporter`: the whole database, which File > Import File in Ghidra and `GhidraProject` open again) to the absolute `path` (same rules as `export_header`; an existing file is overwritten). **It exports what is in memory:** unsaved edits are included, the project's stored copy is neither read nor changed (so the archive can be newer than the saved program; `undo_state.dirty` is unchanged). | `xrefs_to` | `{address, limit?=500}` | `[{from, type, kind, function?}]` | Memory references to `address`, ascending by `from`. `type` is the Ghidra RefType name (e.g. `UNCONDITIONAL_CALL`); `kind` classifies it: call\|jump\|read\|write\|readwrite\|data\|flow\|other; `function` names the function containing `from`. |
| `function_calls` | `{entry}` | `{callers[], callees[]}` | The functions that call the function at `entry` and the functions it calls (`Function.getCallingFunctions` / `getCalledFunctions`, each function once however many call sites). | `list_bookmarks` | `{type?, query?, offset?=0, limit?=100 (max 1000), sort?="address", desc?=false}` | `{total, types[{type, count}], items[{address, type, category, comment}]}` | One page of the program's bookmarks (Ghidra's `BookmarkManager`). | `xrefs_to_variable` | `{entry, name, limit?=500}` | `[{from, type, kind, function?}]` | References to the stack or register variable called `name` of the function at `entry` (a parameter or stack local, e.g. `param_1`, `local_10`, or one the user renamed; what the decompiler token under the cursor names). Variables the decompiler invents (`iVar1`, register temporaries) and globals have no program variable: result `[]`; use `variable_uses` for those (the client calls it when this returns `[]`). `NotFound` if no function at `entry`. |
| `variable_uses` | `{entry, name, timeoutSecs?=30}` | `[{from, type, kind, function}]` | Uses, inside the function at `entry`, of the decompiler variable `name` (the name shown in the decompiler: `iVar1`, `uVar3`, `unaff_RDI`, a parameter; not globals: those have an address, see `varAddress`): its definition(s) with `kind` `write` and the ops that read it with `kind` `read`; `from` is the instruction address of the op, `type` the p-code mnemonic (`INT_ADD`, `CALL`, `COPY`...). Sorted by address; phi and INDIRECT ops are not listed; a parameter's implicit definition at function entry is not a write. `[]` for an unknown name. A separate method (not a fallback inside `xrefs_to_variable`) because it runs a decompile: it is a **decompiler-lane** request (unique request id, cancellable with `cancel_decompile`, `Timeout`/`Cancelled` as `decompile`), while `xrefs_to_variable` is a cheap thread-R read. The uses of all variables of the function come from one decompile and are kept in the decompile cache (same invalidation), so the next variable of that function is a cache hit. `NotFound` if no function at `entry`. |
| `xrefs_from` | `{address}` | `[{to, type, kind, target, label?}]` | References from the instruction at `address`. `target` is memory\|stack\|register\|external; only `memory` has `to` (address), the others have `to` null and a display `label` (`Stack[-0x10]`, `RAX`, the external symbol's name). |
| `list_strings` | `{offset?=0, limit?=500 (max 5000), minLength?=4, query?, referencedOnly?=false}` | `{total, items:[{address, value, length, refs, refFrom?}]}` | Defined strings in address order; `query` is a case-insensitive substring filter on the value; `referencedOnly` keeps only strings that something references (non-boolean: `InvalidArgument`); `total` counts all matches (after `minLength`, `query` and `referencedOnly`), `items` is the page. `refs` is the number of references to the string's address; when `refs > 0`, `refFrom` lists the first 3 of them as `{from, function?}` (`function` = the containing function's name; `xrefs_to` has the full list). `value` is cut at 1000 UTF-16 units (`length` is the byte length of the defined string). The first call per `minLength` scans every string (seconds on a big binary), later pages are served from the snapshot until the next program change. Scan request. |
| `search_memory` | `{pattern, kind?="bytes", encoding?="ascii", caseSensitive?=true, start?, limit?=1000 (max 10000)}` | `{items:[{address, length, bytes, function?}], next}` | Ghidra's memory search (`ghidra.features.base.memsearch`: `UserInputByteMatcher` + `MemorySearcher`, the same code as the GUI's Search Memory) over the loaded, initialized address set, ascending. `kind` `bytes`: hex bytes with wildcards (`48 8b ?? 24`; `?` or `.` = any byte), `text`: the string `pattern` encoded as `encoding` ∈ ascii\|utf16le\|utf16be (`caseSensitive` applies to text). One call returns one page of at most `limit` matches; `next` is the address to pass as `start` for the following page, `null` = the whole set has been searched. `bytes` is the matched bytes in hex (first 16), `function` the function containing the match. `InvalidArgument` for an empty or unparsable pattern (message from Ghidra), unknown `kind`/`encoding`, `limit` < 1, malformed `start`. Scan request; a cancelled page fails with `Cancelled` and returns nothing (earlier pages stay valid). |
| `cancel_search` | `{id}` | `{cancelled}` | Cancels the scan request (`search_symbols`, `list_symbols`, `list_strings`, `search_memory`) with that JSON-RPC id, queued or running; that request fails with `Cancelled`. `false` if unknown or finished. Handled on the event loop. |
| `get_bytes` | `{address, length}` | `{address, length, bytes}` | The bytes at `address` as lowercase hex separated by spaces (`48 8b 05`), the same spelling as a listing row's `bytes`. `length` is an integer from 1 to 65536 (64 KiB); `InvalidArgument` outside that range or for a bad address. **Unmapped or uninitialized bytes are an error, not a marker:** if any byte of the range is not loaded and initialized memory of the address's space (also a range that runs past the end of the space), `NotFound` and nothing is returned. Lane R. Capability `bytes`. |
| `get_comments` | `{address}` | `{eol?, pre?, post?, plate?, repeatable?}` | The comments of the code unit containing `address`, only the kinds that are set (`{}` = none). `NotFound` if there is no code unit there, `InvalidArgument` for a bad address. Same addressing as `set_comment`. |
| `list_data_types` | `{query, limit?=50}` | `[{name, path, size, kind, source}]` | Substring match on data type names (program + built-ins; `source` is `program` or `builtin`, a program type shadows a built-in of the same path); `size` -1 = dynamic/unsized, `kind` as in *Data types*. |
| `load_coverage` | `{path}` | `{ranges:[{start,end}]}` | Reads a text file of executed code: one `0xSTART-0xEND` (END inclusive) or `0xADDR` per line, `#` comments and blank lines skipped. `NotFound` if the file is missing, `InvalidArgument` for a bad line (the message names it), a file over 32 MB or over 1,000,000 ranges. Pure parse, nothing is stored in the program; the client keeps the ranges and tints the listing. |
| `undo_state` | `{}` | `{canUndo, canRedo, undoName?, redoName?, dirty}` | Current undo/redo availability and labels; `dirty` = unsaved changes since open or the last `save` (Ghidra `Program.isChanged()`). Undoing back to the saved state makes it clean again (measured: Ghidra tracks this). |

### Edits
Each edit is one Ghidra transaction, named as the undo label (e.g. "Rename symbol"), runs on thread R, and fires `program_changed`. Result `{}` unless noted.
| method | params | result | semantics / errors |
|---|---|---|---|
| `set_bookmark` | `{address, category, comment}` | `{}` | A `Note` bookmark on the code unit containing `address`. Ghidra keeps one bookmark per address, type and category, so the same category at the same unit replaces the comment. One transaction "Set bookmark", fires `program_changed` kind `bookmark` with that unit's address. `InvalidArgument` for an address not in memory. `Busy` during analysis, like every edit. |
| `remove_bookmark` | `{address, type}` | `{}` | Removes every bookmark of `type` (all categories) at `address` (exactly the unit's start address as `list_bookmarks` shows it). One transaction "Remove bookmark", kind `bookmark`. `NotFound` if there is none. |
| `rename_symbol` | `{address, newName}` | `{}` | Renames the function or label at `address`. `NotFound` if there is none; `InvalidArgument` for an invalid or duplicate name. |
| `create_label` | `{address, name}` | `{}` | Creates a user-defined label (Ghidra `AddLabelCmd`) at an address that has no symbol yet; `rename_symbol` renames an existing one. Decision: two methods, so a typo can never create a second label where a rename was meant. `InvalidArgument`: invalid name (empty, whitespace), address not in memory, or a label/function already exists there. Fires `program_changed` kind `symbol`. |
| `set_comment` | `{address, kind, text}` | `{}` | `kind` ∈ eol\|pre\|post\|plate\|repeatable. Empty `text` clears the comment. |
| `create_function` | `{address, name?}` | `{entry, name}` | Creates a function at `address` (default name if omitted). `InvalidArgument` if one can't be created there or the name is invalid/duplicate. |
| `set_function_signature` | `{entry, signature}` | `{}` | `signature` is a C prototype, e.g. `int foo(int a, char *b)`. `NotFound` if no function at `entry`; `InvalidArgument` if unparsable. |
| `rename_variable` | `{entry, name, newName, timeoutSecs?=30}` | `{}` | Renames a decompiler local/param by name. Decompiles on a scan worker, bounded by `timeoutSecs` (`Timeout` -32003 when exceeded, nothing written), then commits on R after a state check. Cancellable with `cancel_decompile` (`Cancelled`). `NotFound` if function or variable is missing; `InvalidArgument` for an invalid/duplicate name. |
| `retype_variable` | `{entry, name, dataType, timeoutSecs?=30}` | `{}` | Retypes a decompiler local/param. Timeout and cancel as `rename_variable`. Only fixed-length types are accepted; `InvalidArgument` for an unknown, unparsable or dynamic-size type. |
| `define_data` | `{address, dataType}` | `{}` | One transaction "Define data": Ghidra `CreateDataCmd` with force (clears conflicting *data*, never instructions). `dataType` is a name or path as in `retype_variable` plus arrays/pointers (`int`, `char[4]`, `char *`, `dword`, `/dword`). `InvalidArgument`: unknown/unparsable type, dynamic or zero-size type (e.g. `string`, `void`), address not in memory, an instruction in the way, no room. A failure rolls back (nothing on the undo stack). Fires `program_changed` kinds `data`, `code` with the data's range. |
| `clear_code` | `{address, length?}` | `{}` | One transaction "Clear code": Ghidra `ClearCmd` (instructions and data; not symbols/comments) over `[address, address+length-1]`, default the code unit containing `address`. Like the listing's "Clear Code Bytes", units overlapping the range are cleared whole (so a range inside one defined unit clears that unit). `InvalidArgument`: address not in memory, `length` < 1, or nothing but undefined bytes in the range (nothing would change). Fires `program_changed` kinds `code`, `data`. |
| `save` | `{}` | `{saved, undoHistoryCleared}` | Writes the program to the project. `saved=false` if nothing had changed. Runs on thread R; safe while decompiles run. **Ghidra drops the undo/redo history on save**; a saving call also fires `program_changed {ranges: [], kinds: [], undo}` (nothing to refetch, `undo` is the new state with `dirty=false`). |
| `undo` | `{}` | `UndoState` | Undoes the last edit. `InvalidArgument` if nothing to undo. |
| `redo` | `{}` | `UndoState` | Redoes the last undone edit. `InvalidArgument` if nothing to redo. |

### Listing pages

`listing_rows` walks code units from an anchor, no index. `forward`: starts at the code unit containing `address` (or the next one if `address` is in a gap) and goes up. `backward`: the `count` code units strictly before the one containing `address`, returned in ascending order. Both are restricted to the loaded+initialized set; fewer than `count` rows means the end (or start) was reached. `count` is capped at 1000. The walk continues across address spaces in the order of `listing_info`. A row is one code unit (instruction, defined data, or one undefined byte); `bytes` shows at most 16 bytes and `bytesMore` says how many more the unit has (`get_bytes` fetches them). Row fields (`ListingRow` in `protocol.ts`):
- `label` the primary symbol; `labels` all symbols at the address, primary first, only when there is more than one.
- `comment` is the EOL comment; `pre`, `post`, `plate`, `repeatable` the other kinds (multi-line text), each only when set. The client renders plate and pre above the row, post below it, EOL and repeatable at the end of the line.
- `header` on a function's entry row: `signature`, `convention`, `params` (count), `paramBytes` / `localBytes` (stack frame sizes), `noReturn`, `thunk`.
- `xrefs` `{count, items}` when memory references point at the address: `count` is the full number, `items` at most 5 (shortcut: the first 5 Ghidra returns, shown ascending by from; the full list is `xrefs_to`), each `{from, kind}`.
- `bookmarks` `[{category, comment}]` when the user has a `Note` bookmark on the unit (the analyzers' bookmark types are not marked; `list_bookmarks` has them).
- `parts` for defined structure/union/array data: components `{offset, length, type, name, value}` (arrays name elements `[i]`), at most 64 (`partsTotal` is the real count when cut; shortcut: one level, nested composites show as one component with their display value). The client folds them by default.
Row building stays on thread R and costs a few Ghidra calls per row; bench numbers are in SPIKE_REPORT.

## Tokens
`line` is 0-based into `text.split("\n")`. `colStart/colEnd` index into that line (indent included). `kind` follows Clang syntax types. `targetFunction` is set on call-target name tokens when the callee entry is known (thunks are followed to the entry of the called function symbol itself, not resolved).

## Analysis
- **When.** `open_binary` (background) publishes the program as soon as the import is saved: listing, function list, decompile and navigation work while analysis runs. Analysis runs on its own thread (lane A), never on R, so reads keep their latency. State: `AnalysisState` (`protocol.ts`), pushed as `analysis_state` and readable with `analysis_status`.
- **Ghidra's rules (SPIKE_REPORT, Round 7).** The whole analysis is one open Ghidra transaction. A second transaction on the same program does not wait, it *joins* the open one, so an edit made meanwhile could neither be undone alone nor survive an analysis rollback; Ghidra's own GUI blocks edits and disables undo while it analyzes. We do the same: **edits, `undo` and `redo` fail `Busy` ("analysis running")** until the analysis ends or is cancelled. Reads need no transaction and interleave with the analysis per database operation. The analysis is never on the undo stack (`clearUndo` when it ends).
- **Events.** While analysis runs, `program_changed` is coalesced to about one per second with `ranges: null` and all kinds; the decompile cache and the symbol/string snapshots are invalidated on every batch. A client refreshes what it shows (function list, visible listing rows) without resetting scroll or selection.
- **Persistence.** `programs.json` records `analysis` (`none` after import, `partial` as soon as an analysis starts, `done` when one finishes) and `analysisProfile`. The analysis is saved to the project when it finishes or is cancelled. An interrupted analysis (cancel, `close_program`, `save`, shutdown, or a crash before the final save) leaves `partial`; opening the program again resumes it (Ghidra's re-analyze command: finished regions are cheap, not free). A crash loses the in-memory analysis of the interrupted run.
- **`save`, `close_program`, shutdown during analysis** cancel it first (waiting for it to stop), then save as usual.
- The `fast` profile and the persistence key are unchanged: `start_analysis {profile: "full"}` on a fast program keeps its `programId`.

## Debugger
`debugger` capability. The sidecar speaks the GDB Remote Serial Protocol over TCP itself (QEMU's `-gdb tcp::1234` stub): `qSupported`, `qXfer:features:read` (target.xml and what it includes), `?`, `p`, `m`, `Z0`/`z0`, `c`, `s`, Ctrl-C, `D`. State: `DebugState` (`protocol.ts`), announced as `debug_state`; the methods' results are empty (`debug_status` returns the state).

| Method | Params | Notes |
|---|---|---|
| `debug_attach` | `{host?="localhost", port?=1234, offset?="0x0"}` | Connects, reads the register description, stops the target (QEMU started with `-S` is already stopped) and installs the breakpoints. `Target` error: `Connection refused by host:port…`, `Unknown architecture…` (the target's architecture is not the program's processor, or the program counter is not among its registers), `The target is not stopped`. `Busy` if already attached. |
| `debug_detach` | `{}` | Detaches (`D`) and closes. The breakpoints stay. |
| `debug_breakpoint` | `{address}` | Toggles a breakpoint at the program address (`Z0`/`z0` at address + offset when attached; otherwise only remembered and installed on the next attach). While the target runs it is stopped, changed and resumed without announcing a stop; `Busy` only during a statement step. |
| `debug_continue` | `{}` | Resumes (first one instruction off a breakpoint at the pc, like gdb). `state` `running` is announced, the next stop arrives as `stopped`. |
| `debug_step` | `{mode?="instruction", boundaries?}` | `instruction`: one instruction, then `stopped` is announced. `statement`, `into` and `out` (the first two need `boundaries`: the program addresses where a statement of the pc's function starts, at most 5000, taken from the client's decompiler line mapping so the stop and the highlight agree): `running` is announced and the target is stepped instruction by instruction until the pc is at a boundary (`statement`, `into`), at a breakpoint, or outside the function (a return stops in the caller; `into` also stops at a callee's first instruction). `statement` and `out` run a call over with a temporary breakpoint after it (a deeper recursive frame returning to the same address is told apart by sp). `out` has no boundaries: it runs to the return. `debug_pause` ends any of them; after 20000 instructions they stop where they are. `InvalidArgument` without boundaries where needed. |
| `debug_memory` | `{address, length?, dataType?}` | Up to 4096 bytes of the stopped target's memory at a *runtime* address (register values are runtime addresses, `offset` is not applied): `{address, bytes (hex), items?}`. With `dataType` (a type name or path known to Ghidra, `uint[4]`, `/MyStruct`) `items` has one entry per component of a structure or array (at most 256), else one: `{offset, length, type, name, value}`, the value as Ghidra displays it. `length` defaults to the type's size (else 64). `Busy` while running; `Target` error when the memory is unreadable; `InvalidArgument` for an unknown type. |
| `debug_values` | `{entry}` | Scan lane. The decompiler's parameters, locals and the globals the function at `entry` uses, with their value in the stopped target: `{pc, items:[{name, kind, type, size, where, value, raw}]}`. Stack variables are read at sp-at-entry + offset (sp-at-entry = sp minus Ghidra's stack depth at the pc), register variables from the stop's register values (not checked for liveness), globals at their address (+ `offset`). Variables the decompiler keeps in no fixed place, or that cannot be read, are left out. |
| `debug_pause` | `{}` | Ctrl-C; the stop arrives as `stopped`. `Busy` if not running. |
| `debug_status` | `{}` | The current `DebugState`. |

On every stop the sidecar reads the registers the program's language knows (names from Ghidra, numbers from target.xml; registers wider than 128 bits are left out) and announces `stopped` with `address` (the pc minus `offset`) and `registers`. A stop on a signal other than the single-step trap (SIGTRAP) or our own interrupt (SIGINT) carries `signal`, and a step or continue that meets one ends there instead of going on. The target exiting (`W`/`X` stop reply) or the socket closing announces `detached` with an `error`. `offset` is 0 for now: program addresses are runtime addresses. The state belongs to the program session: another session drops the connection. Debug requests on thread R.

## Notifications (server → client, no id)
- `debug_state {sessionId, state, target, stop, offset, breakpoints, address?, registers?, signal?, error?}` — see Debugger.
- `analysis_state {state, analysis, profile, analyzer, done, pct, error?}` — an analysis started, progressed (about every 250 ms when something changed) or ended (`done`, `cancelled`, `failed`).
- `progress {openId, phase, pct, message, analyzer?, done?, total?}` — phase order: `import` → `analysis` → `saving` → `ready` (only while `open_binary` runs; a persisted program goes straight to `ready`). `pct` is 0–100 or -1 (indeterminate). During `analysis` `pct` is -1 because Ghidra's AutoAnalysisManager has no global total; `analyzer` is the current analyzer name; `pct` is the per-analyzer progress/max when that analyzer reports a maximum (else -1); `done` is the number of analyzer runs finished so far; `total` is omitted.
- `program_changed {sessionId, ranges, kinds, undo}` — the program was modified. `ranges` is `[{start,end}]` (Ghidra address ranges, space-qualified, `end` inclusive, both ends in one space) or `null` = unknown/broad, refetch everything. Type changes (`kinds` has `type`) always carry `null`: Ghidra's type events have no address. A client refetches only the listing rows that intersect `ranges`. `kinds` ⊆ symbol|comment|function|data|code|type|bookmark|other tells the client what to refetch. `undo` is the new `UndoState` (including `dirty`). Events from edits and `undo`/`redo` are coalesced over ~50 ms. A save sends `ranges: []`, `kinds: []` with the new undo state. Events already queued for the active program can arrive while `open_binary` stages a replacement. Closing or replacing that program drops its remaining pending events.
- `error {message}` — non-fatal, out-of-band.

## Errors
Standard JSON-RPC error object. Codes in `protocol.ts` `ErrorCode`: NoProgram -32001, Cancelled -32002, Timeout -32003, NotFound -32004, Busy -32005 (open in progress / second `open_binary` / an edit while the analysis runs, message "analysis running"), ProjectLocked -32006, StaleSession -32007, Target -32008 (the debug target: refused, lost, unknown architecture, not attached), InvalidArgument -32602, MethodNotFound -32601, Internal -32603.

`ProjectLocked` (-32006): another sidecar (another Ghidrette) holds the projects dir; message `projects dir in use by another Ghidrette (<dir>)`. Returned by every request that touches the project (`open_binary`, `import_candidates`, `list_programs`, `delete_program`); the sidecar stays up and the next call retries, so it works once the other instance has quit. `list_languages` and the rest are unaffected.

## Concurrency
- **Thread R** (the event loop dispatches to it) handles the cheap program reads (`list_functions`, `listing_*`, xrefs, ...) and ALL writes, `undo` and `redo`, in arrival order.
- `save`, `close_program` run on R like edits (in order); `import_candidates`, `list_languages`, `list_programs`, `delete_program` also run on R (they touch the project or loaders only when no open is running, hence `Busy` during an open; `close_program` waits for running decompiles to be cancelled as in `_close`). `open_binary` saves the current program before replacing it; a save failure keeps it open.
- **Thread O** validates and stages the replacement for `open_binary`. Thread R commits the swap after staging succeeds. While an open is in progress, program requests fail fast with `NoProgram`, and a second `open_binary` fails with `Busy`. **Thread A** runs the background analysis (see *Analysis*), one at a time, never on R; `cancel_analysis` and `analysis_status` are answered on the event loop. The thread `open_binary` stages on (O) also runs the analysis in `analysis: "blocking"` mode.
- `cancel_open` is handled on the event loop (bypasses the queues): it cancels the TaskMonitor, `open_binary` fails with `Cancelled`, nothing is saved to the project, and the sidecar stays usable.
- **Slow reads (scan workers, thread S)**: `search_symbols`, `top_symbols`, `list_symbols`, `list_strings`, `search_memory`, `list_data_types`, `export_symbols` and `export_header` run on M threads (env `SIDECAR_SCAN_WORKERS`, default 2) with their own queue, so a multi-second scan or search never delays `listing_rows` or edits on R. They read the program concurrently with R (Ghidra's database locking), are cancellable by request id (`cancel_search`), and are cancelled when the program is closed or replaced (`close_program` waits for them like for decompiles). Their cached snapshots (symbol table views, string scans) are dropped on every `program_changed`. A page read racing an edit (`list_symbols` meeting a symbol the edit deleted after the snapshot was taken) is retried once on a fresh snapshot; only if a second edit races the retry does it fail with `Cancelled` ("program changed while reading, retry"). The client refetches on `program_changed` anyway.
- **Decompiler pool**: N threads (env `SIDECAR_DECOMP_WORKERS`, default 2), each owning its own `DecompInterface` and all sharing one queue; `decompile`, `variable_uses` and `function_graph` run there. A slow decompile never delays listing fetches. `cancel_decompile` (event loop, bypasses queues) works by request id for queued and running requests.
- **Decompile cache**: shared and thread-safe, keyed by function entry (address space and offset; `variable_uses` results are cached next to it), invalidated on `program_changed` (functions overlapping the changed ranges; `ranges` null or kind `type` clears everything), so results are never stale (`cached` is false after an invalidating edit).
- `rename_variable` / `retype_variable` / `auto_create_structure` prepare on scan workers with a short-lived `DecompInterface`, then commit on R only if the program generation and write revision still match. An intervening write returns `Cancelled` so the client can retry. `load_coverage` parses in a file thread and checks the program generation before returning. Each connection admits at most 64 outstanding requests; messages are limited to 2 MiB and worker queues to 128 items. Disconnect cancels queued work and active decompile/search monitors.

## Persistence and crash safety
- Edits live only in Ghidra's in-memory buffers until saved. The sidecar saves (1) on explicit `save`, (2) automatically when a program is closed (`close_program`, or `open_binary` replacing it), (3) on shutdown (stdin EOF, SIGTERM). There is no discard prompt: unsaved edits are always written. Shutdown waits for a running save (a save lock) and for the close-save on thread R, then closes the project (lock files removed; measured: before Round 5 `spike.lock` and `spike.lock~` stayed behind after every exit) before `os._exit`; it logs `close save took ...` / `shutdown: close finished in ...` on stderr. Saving needs no open transaction (edits end theirs) and works while a decompile runs.
- Dirty: `UndoState.dirty` is `program.isChanged()`. A freshly imported, analyzed and saved program is clean. Undoing back to the last save point is clean again; redo is dirty. Ghidra clears the undo/redo stacks on save.
- Atomic: saving an already persisted program is crash-safe (BufferMgr writes a copy `tmp*.ps`, fsyncs, then renames it to the next `db.N+1.gbf`); killed before the rename = the old version is intact.
- SIGKILL or power loss can lose edits since the last save or completed recovery snapshot. Every `SIDECAR_SNAPSHOT_SECS` (default 120, 0 = off), R can snapshot unsaved changes through Ghidra's DB handle while preserving undo history. The sidecar logs whether the snapshot is current or deferred. The next `open_binary` loads with `okToRecover` and restores the edits as dirty.
- A kill during the first save of a newly imported program (`createDatabase`) can leave a partial `db.1.gbf`. `open_binary` reports the load error and preserves the stored item. Restore the project from a backup, or use `delete_program` and reopen the original binary to explicitly start a fresh analysis.
- **Measured** (`test_raw_import_options_save_reopen_dirty_undo`): saving a changed program clears both the undo and the redo stack, so the client treats save as an undo barrier; `save` on a clean program does nothing and keeps the redo stack.

## Auth
`SIDECAR_TOKEN` is mandatory: the sidecar exits with status 2 and a stderr message when it is unset or empty, unless `SIDECAR_ALLOW_NO_AUTH=1` is set (test-only escape hatch). The WebSocket path is `/<token>`; the mock server ignores the token.
